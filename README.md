# glyph-cipher

Обфускация текста на эффекте «кембриджского университета» (typoglycemia) + leet + гомоглифы + невидимые Unicode-символы. Человек (и сильный LLM с контекстом) читает, а классические парсеры, регулярки и AI-детекторы — спотыкаются.

## Уровни

| Уровень | Приёмы | Человек читает | Токенизатор LLM |
|---|---|---|---|
| `light` | перемешивание средних букв слов | легко | почти нормально |
| `hard` | + leet (е→3, о→0, а→4, т→7) | медленно, но ок | ломается на мусорных токенах |
| `extreme` | + Unicode-гомоглифы + zero-width разделители | ребус | полный распад токенизации |

## Использование

```bash
python3 glyph_cipher/cli.py demo                          # пример всех уровней
python3 glyph_cipher/cli.py encode -l hard -s 42 "текст"  # зашифровать
echo "<шифр>" | python3 glyph_cipher/cli.py decode        # расшифровать
python3 glyph_cipher/cli.py encode -l light -d dict.txt "текст"  # декод с анаграммным словарём
```

Маркер уровня зашит парой zero-width символов в начале текста — decode сам определяет уровень. Seed делает shuffle детерминированным (воспроизводимо).

## Зачем / границы

Исследовательский прототип по мотивам исследований:
- Creo et al. 2025, «Evading AI-Generated Text Detectors using Homoglyphs» (ACL GenAIDetect) — гомоглифы ломают AI-детекторы
- promptfoo red-team strategy «Leetspeak» — обход модерации кодированными входами
- Invisible Unicode / ASCII smuggling (zero-width, tag chars) — скрытые инструкции мимо глаз и фильтров

Практика: приватные заметки, которые не должен индексировать пассивный AI-скан, стресс-тест собственных парсеров и модерации.

НЕ криптография: восстановление возможно и человеком, и сильным LLM по контексту. От целенаправленной слежки не защищает — только от массового автоматического сканирования.
